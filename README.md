# ClauseCheck · 계약서 위험조항 점검

계약서 텍스트를 브라우저 안에서만 점검해, 위험한 문구와 빠진 보호 조항을 찾아 주는 정적 웹앱입니다.
프리랜서 용역·외주, 프랜차이즈·가맹, 임대차, 근로·위촉, NDA, 구독·서비스 약관을 대상으로 합니다.

> **참고용 자동 점검이며 법률 자문이 아닙니다. 법령 요건을 판정하지 않습니다. 중요한 계약은 반드시 전문가에게 확인하세요.**

## 무엇을 하나요

- **입력**: 계약서 텍스트를 붙여넣거나 `.txt` 파일을 불러옵니다. PDF·이미지·워드 파일은 읽지 않습니다.
- **조항 나누기**: `제N조`, 번호 목록(`1.`, `1)`, `(1)`, `①`, `가.`), `Article N`, 빈 줄(문단) 기준으로 나눕니다.
- **위험 문구 점검**: 규칙 34개가 조항 안의 한국어·영어 문구를 찾아 원문에 색으로 표시합니다. 심각도(높음·중간·참고)별 목록을 누르면 해당 위치로 이동합니다.
- **누락 점검**: 원문 어디에도 없는 보호 조항을 체크리스트로 보여 줍니다(규칙 12개). 예: 대금 지급 기한, 해지 조항, 책임 한도, 권리 귀속, 검수 기준, 자료 반환·파기.
- **확인 필요 표시**: 60일, 2개월, 3개월 같은 기준값이나 정보공개서, 근로자성, 소비자 해지·환불처럼 법령이나 관행을 참고한 항목에는 `확인 필요` 표시를 붙입니다(15개 규칙). 임의 기준이며 법령 판정이 아닙니다. 기준일은 2026년 11월입니다.
- **항목별 확인 상태**: 각 위험 문구와 누락 항목에 `확인함`, `협상 필요`, `수용` 중 하나를 정할 수 있습니다. 상태는 점검 기록과 함께 이 브라우저에 저장됩니다. `수용`으로 정한 문구는 원문에서 흐리게 보입니다.
- **버전 비교**: 이전 버전과 새 버전의 원문을 붙여넣으면, 규칙 단위로 새로 생긴 위험, 사라진 위험, 발견 횟수가 바뀐 위험, 새로 빠진 보호 조항, 채워진 보호 조항을 보여 줍니다. 결과는 저장하지 않습니다.
- **위험 점수**: 발견 규칙의 심각도 가중치를 합산해 0~100점과 등급(낮음·보통·높음)을 냅니다.
- **협상 이메일 초안**: 발견한 항목으로 로컬 템플릿 이메일을 만듭니다. 상대방·내 이름, 회신 희망일, 추가 메모, 확인 질문 포함 여부를 채울 수 있고, 만들어진 초안은 직접 고칠 수 있습니다.
- **인쇄용 보고서**: 점수, 확인 상태, 위험 조항, 누락 체크리스트, 면책 문구와 기준일을 한 장의 보고서로 인쇄합니다. Markdown 파일과 발견 목록 CSV도 받을 수 있습니다.
- **가리기(마스킹)**: 주민등록번호, 전화번호, 이메일, 계좌번호, 금액, 지정한 이름을 가린 텍스트를 미리 보고 복사할 수 있습니다.
- **저장과 백업**: 점검 기록을 이 브라우저에 저장하고, JSON으로 백업·가져오기를 할 수 있습니다.
- **AI 설명 (선택)**: 아래 "AI 기능" 절을 보세요.

### 규칙 목록 (요약)

- 위험 문구 34개: 자동 갱신 + 위약금, 해지 통보 기간, 위약금·손해배상 상한 없음, 무제한 책임·간접손해, 일방적 해지, 일방적 변경, 대금 지급 60일 초과, "검수 후 지급"의 기한 불명확, 지식재산권 전부 양도, 2차 저작물, 포트폴리오 금지, 비밀유지 기간 무기한, 비밀정보 범위 과다, 경업금지·전속, 재하도급 금지, 관할 법원(상대방 소재지), 분쟁 비용 전가, 검수 기준 재량, 수정 횟수 무제한, 하자보수 기간 무기한, 대금·보증금 일방 상계, 보증금 공제·반환 거부, 원상복구 범위, 임대료 일방 인상, 수습 기간, 사유 없는 해고, 근로자성 쟁점, 연장·야간 수당 포괄 문구, 해지 방법 제한, 무료 체험 후 자동 결제, 환불 불가, 가맹금 반환 불가, 판매가격 지정, 영업지역 보장 없음.
- 누락 점검 12개: 대금·급여 지급 기한, 해지 조항, 책임 한도, 결과물 권리 귀속, 선금·착수금, 검수 기준, 계약 기간, 보증금 반환 기한, 관할·준거법, 정보공개서 제공 확인, 수정 횟수 제한, 자료 반환·파기.

각 규칙에는 한국어·영어 정규식, 위험 이유, 협상 제안 문구, 확인 질문이 들어 있습니다. 법률 근거 조문은 적지 않았습니다. 규칙 문구는 일반적인 표현에 기반한 것이며, 특정 법령의 요건을 판정하지 않습니다.

## 실행 방법

빌드 단계가 없습니다. ES 모듈 때문에 `file://`로 열면 동작하지 않습니다.

```bash
cd clausecheck
python3 -m http.server 8141   # 또는 8141~8149 중 비어 있는 포트
# 브라우저에서 http://localhost:8141 열기
```

화면 글꼴(Noto Serif KR)은 Google Fonts에서 불러옵니다. 불러오지 못하면 시스템 세리프 글꼴로 대신 보입니다.

## 테스트

Node 18 이상에서 실행합니다. 외부 패키지는 필요 없습니다.

```bash
node --test tests/logic.test.js
```

테스트 내용 (총 159개):

- 각 위험 규칙마다 **양성 예시(걸려야 함)와 음성 예시(걸리면 안 됨)**를 둡니다.
- 각 누락 규칙마다 보호 문구가 없을 때 누락으로 나오고, 있으면 나오지 않는지 확인합니다.
- 확인 필요(`legalRef`) 표시가 정확히 붙는지, 위험 34개·누락 12개 규칙 수를 확인합니다.
- 조항 나누기: 제N조, 번호 목록, Article N, 빈 줄, 제목만 있는 줄, CRLF, 원문 위치(offset) 일치.
- 마스킹: 주민번호, 전화, 이메일, 계좌(문맥형·대시형), 금액, 이름(정규식 문자 이스케이프 포함), 옵션 끄기.
- 항목별 상태: 키의 안정성, 잘못된 값 거르기, 백업·이전 기록 호환, 요약 집계.
- 버전 비교: 같은 텍스트, 추가·삭제·횟수 변화, 보호 조항 변화, 상한에 걸린 점수 차이.
- 협상 메일 옵션, 보고서 모델과 Markdown·CSV의 상태·확인 필요 표시.
- 성능: 200KB 적대적 입력(반복 패턴, 긴 숫자열, 많은 줄)을 분석하는 데 200ms 미만이어야 합니다.
- 정규식은 모두 선형 시간에 동작하도록 작성했습니다. 중첩 수량자는 쓰지 않고, 임의 문자열은 `[^\n]{0,N}`처럼 길이를 제한합니다. 테스트가 중첩 수량자 패턴을 검사합니다.
- AI 보조 함수: 전송 내용 크기 제한, 응답 검증, 키 형식 확인, 로컬 대체 설명 (네트워크 호출 없음).

브라우저 점검은 Playwright로 390×844와 1280×800, 라이트·다크 모드에서 확인했습니다. 샘플 점검, 상태 변경과 저장 후 다시 열기, 메일 편집, 인쇄 호출과 보고서 내용, 가리기, 버전 비교, AI 키 없이 전송 없음을 확인했고 가로 넘침과 콘솔 오류는 없었습니다.

## 데이터와 개인정보

- 계약서 원문은 서버로 보내지 않습니다. 점검은 브라우저의 JavaScript가 처리합니다.
- 저장 기록은 `localStorage`(키 `clausecheck-reviews`)에 있습니다. 항목별 확인 상태도 같은 기록에 들어갑니다. 원문 저장 옵션을 끄면 점검 요약(점수, 발견 목록, 누락 목록, 확인 상태)만 저장합니다.
- 저장소를 지우면 기록도 사라집니다. JSON 백업을 받아 두세요.
- 가리기 설정은 복사·미리보기에 적용됩니다. 가리기 자체는 완벽하지 않으니 복사 전에 직접 확인하세요.
- 모든 화면 출력은 `textContent`로만 넣고 `innerHTML`은 쓰지 않습니다. 계약서 문구가 스크립트로 실행되지 않습니다.

## AI 기능 (선택)

AI 설명 패널은 **버튼을 누를 때만** 동작합니다.

- 사용자가 직접 입력한 Anthropic API 키로 `https://api.anthropic.com/v1/messages`를 브라우저에서 직접 호출합니다. 모델은 `claude-haiku-5-5`, `max_tokens`는 700입니다.
- **전송 내용**: 사용자가 고른 조항(최대 5개)의 원문을 가리기 처리한 텍스트, 각 항목의 점검 제목·심각도·점검 이유, 그리고 고정 지시문입니다. 계약서 전체, 점검 기록, 항목별 상태, 이름·연락처 등 가리기 전 원문은 보내지 않습니다. 전송 내용은 버튼 옆 미리보기에 그대로 표시됩니다.
- 키가 없거나 호출이 실패하면 규칙에 적힌 위험 이유와 협상 문구를 같은 레이아웃으로 보여 줍니다.
- 응답은 JSON 형식을 검증해 쓰고, 형식이 맞지 않으면 원문 일부만 표시합니다. 모든 출력은 `textContent`로 넣습니다.
- 키를 저장하려면 체크박스를 켜야 하며, 저장된 키는 `localStorage`(`clausecheck-ai-key`)에 있습니다. **브라우저 저장소의 키는 개발자 도구에서 보일 수 있으니 공용 PC에서는 저장하지 마세요.** 저장된 키는 "저장된 키 지우기"로 삭제합니다.
- 요청 로직과 응답 파싱은 `ai.js`에 있고 테스트가 있습니다. 실제 API 호출은 이 환경에서 키가 없어 **검증하지 못했습니다.** 응답 형식이 바뀌면 `parseAiReply`가 원문 표시로 물러나도록 되어 있습니다.

## 파일 구성

- `index.html` · `styles.css` · `app.js`: 랜딩, 화면, 이벤트
- `logic.js`: 조항 나누기, 분석, 점수, 마스킹, 버전 비교, 항목별 상태, 보고서 모델, 저장·백업 (DOM 없음)
- `rules.js`: 규칙 데이터 (위험 문구 34, 누락 12, 확인 필요 플래그 `legalRef`)
- `ai.js`: AI 요청 구성, 응답 검증, 키 형식 확인, 대체 설명 (네트워크 호출 없음)
- `tests/logic.test.js`: `node --test` 테스트

## 알려진 한계와 확인이 필요한 항목

- **법령 기준은 검증하지 않았습니다.** 60일, 2개월, 3개월, 5%(임대료 예시 문구), 근로기준법 해고 제한, 가맹사업법 정보공개서, 전자상거래 해지·환불, 포괄임금, 재판매가격 등은 일반적으로 알려진 내용을 참고한 것이며 최신 법령으로 확인하지 않았습니다. 모두 `확인 필요`로 표시하며, 특히 "정보공개서 제공 시기", "수습 기간 상한", "포괄임금 효력", "판매가격 지정 허용 범위"는 전문가 확인이 필요합니다.
- 문구 기반 규칙이므로 같은 뜻을 다른 말로 쓰면 놓칠 수 있고, 반대로 맥락과 무관하게 걸릴 수도 있습니다. 예: 상대방에게 유리한 해지 조항도 "언제든지 해지"로 표시됩니다.
- 버전 비교는 규칙 단위입니다. 같은 규칙 안에서 내용이 바뀌었어도 발견 횟수가 같으면 변화로 보지 않습니다.
- 조항 나누기는 줄 구조에 의존합니다. 표나 한 줄짜리 긴 문단은 하나의 조항으로 묶일 수 있습니다.
- `.txt`가 UTF-8이 아니면 글자가 깨질 수 있습니다. 화면에서 경고를 띄우지만 자동 인코딩 변환은 하지 않습니다.
- 점수는 참고용 지표이며 법적 효력이나 위험의 크기를 뜻하지 않습니다.

## 수익화 메모 (구현하지 않음)
